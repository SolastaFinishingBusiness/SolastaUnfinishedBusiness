- Dungeon Maker, for campaign authors: a campaign can now use campaign variables with reserved names as commands. Dialog_Trigger starts an NPC's or object's dialogue, Roll_Trigger has a character roll a Roll Activator's check, Teleport_Node and Teleport_PartyNode teleport one character or the party to a named gadget (usually a Node), placed nearby as the game's own Teleporter does it, Torches_Lit, Torches_Auto and Torch_<name> switch torches, and the Clock_ variables read the time, count minutes, hours and days, and skip time. A roll or a one-character teleport acts for the character whose move set off the Area Activator or pressure plate, or who used the object, also when that gadget activates another gadget (such as a Variable Operation) that writes the variable, through any number of gadgets, and on through a variable or quest step a Variable or Quest Activator reacts to, a dialogue that gadget starts and the actions of its lines, and a Timed Activator it enables (the targets of a Roll Activator act for the character who rolled, and a button set off by damage for the party member who hit it); the mod's own writes, such as the _Status variables, start no chain; a save made while a command or a chain is waiting keeps its acting character; a campaign that already uses one of the mod's variable names for something of its own is left alone (the mod writes its read-outs and statuses to <name>_2 instead, and ignores a command name the campaign uses for something else); campaign and location files saved in the Dungeon Maker record the mod's version; in the editor, typing one of the mod's variable names shows a hint above the field saying what it does, and typing a gadget name into a command variable that nothing goes by shows a warning with the closest names; when the party arrived together, or the start can't be traced, it acts only if exactly one eligible character is involved. Without one such character it does nothing. When a command fails, a message at the top of the screen says so (for a roll or a one-character teleport, what started it, such as a timer, which can't say who), and the mod's log has a detailed line on what wrote the variable, through which gadgets, and why. Optional <command>_Status variables report Pending, Running, Succeeded, Failed or Cancelled. Players need the mod for a campaign that uses them. They work in every campaign while the mod is installed; a campaign that doesn't create these variables is not affected. The guide is Documentation/DungeonMakerCommands.md on the mod's GitHub page. Thanks to BlackguardRogue for the Dungeon Maker tools this comes from.
- Dungeon Maker: the campaign editor, the variable picker, the Cheats > Campaign Variables panel and the location editor's gadget, prop and room palettes each have a new bar at the top of their lists to search and sort them. Typing in the search field shows only the entries whose name or title contains the text, and Clear empties it; the sort dropdown orders the list by the campaign's own order, by name, or by title (by type for the variables panel), and the arrow beside it switches between ascending and descending. Each list also has a sort of its own kind: in the campaign editor a "Sort:" dropdown and arrow directly under each list's header, which comes first, with the bar's sort breaking ties; the variable picker and the variables panel show a single list, so its own keys are further choices of the bar's one sort, with its one arrow. It starts on Default (the bar's sort alone) and offers keys such as hit points, challenge rating or an ability score for monsters and NPCs, cost for items, start level or map size for locations, or a variable's starting value. While a list is sorted by a field its rows don't show, each row shows its value at its right end; sorted by campaign start, ascending, the starting location comes first. The sort and its direction are shared by the three screens and remembered, and saved as soon as they are chosen; the search is emptied each time a screen opens. If the search hides the selected entry, the selection is dropped. In the campaign editor, folding a list away, by its header or by opening another list with a shortcut icon, drops that list's selection too. Only what is shown changes: the campaign keeps its own order, so nothing is saved differently and auto-start quests still start in the same order. The editor's move arrows only work in the plain view (own order, ascending, no search). In the palettes the sort orders the blueprints inside each category, the categories keep the game's order, and the search hides categories with nothing left to show. A "Categories:" toggle on the sort row (in the palettes at its right end, showing only Default or A-Z, with "Categories" in its tooltip) switches the order of the sections themselves (the editor's lists, the palettes' categories) between the game's order and alphabetical by title. A palette keeps each category folded or open as it was when the location's environment or size changes; a category the new environment adds starts folded. Mod UI > Dungeon Maker has a setting for each of these screens, and under it one for each tool it has (Search, Page sort, Category sort, Category-specific sort; on the variable picker and the variables panel Search and Sort), all on by default; switching a screen off switches its tools off, and a screen with its tools off looks and works as without the mod. The setting "Enable assets sorting on Dungeon Maker editor" is gone: the palettes' Default is the game's own order, and the campaign editor no longer re-sorts the campaign's own lists when it opens. If it was on, the sort starts on Name with the categories A-Z instead.
- Dungeon Maker custom weapons: the weapon tooltip's damage bonus now shows the weapon's total flat bonus, the enhancement of the item it was made from plus the number typed in its Weapon Effects damage box. A +1 weapon with -1 typed in showed +1, and a plain weapon with +2 typed in showed no bonus. The damage breakdown of an attack shows the two as one line named after the weapon (a +1 weapon with +3 typed in shows "+4: <weapon>" instead of "+3: Base" and "+1: <weapon>"), and leaves them out when they add up to 0, also when the game gives the enhancement no name (as on the Main Attack box); holding Alt shows the full breakdown. It applies to any weapon with a damage bonus of its own, though in practice only Dungeon Maker custom weapons have one. Any breakdown (damage, to-hit, or a stat such as armour class) names an item that isn't identified yet by its unidentified name (such as "Magnificent Longsword"), as the inventory does, where the game showed its real name; an item with no unidentified name shows "Unidentified" and its type instead , the most specific one it has (such as "Unidentified Longsword", "Unidentified Chain Mail", "Unidentified Arrow", "Unidentified Scroll", "Unidentified Ring", "Unidentified Musical Instrument", or "Unidentified Wondrous Item" for amulets, cloaks and other worn items), and "???" only if it has no type either.
- Breakdowns (damage, attack, armour class and others): an entry the game listed with no source, shown as "+1:" with nothing after it, now names its source: the item, spell or character it came from, the weapon of the attack shown, or else the kind of source ("+1: Item").
- Weapon tooltips: the damage bonus row showed the weapon's attack bonus. It now shows its damage bonus (they only differ on weapons whose two bonuses are not the same).
- Dungeon Maker editor: variable names the mod uses are coloured wherever the editor shows them: red for names the mod writes itself (clock read-outs and counters, _Status variables), blue for names that make something happen when written (commands such as Teleport_Node, requests, counter switches). The typing hints show only while their field has the focus, and sit below the field in the dialogue and quest editors.
- Dungeon Maker editor: typing the gadget name for Dialog_Trigger, Roll_Trigger, Teleport_Node or Teleport_PartyNode now offers the names that start with what is typed in a small list by the field, the likely ones for that command first. Click one, or use Up and Down with Enter or Tab, to fill it in; Escape closes the list. The location, dialogue and quest editors have a new "?" button beside CLOSE that lists every variable name the mod uses and what it does; the list also opens by itself the first time one of these editors is opened, until "Hide this from now on" is chosen. Mod UI > Dungeon Maker has a new Campaign commands button that opens the guide, which now comes with the mod. Pointing at a variable the mod uses in the variable picker or the campaign's variable list shows what it does. While a location or the campaign map is played with the editor's Playtest button, the commands' error messages start with "Playtest:" and are also added to the game's log.
- Dungeon Maker editor: the hints for the campaign command names say more plainly what each one does (a clock switch names the counter it adds to, a read-out what it holds, each time skip what it moves the clock to). Mod UI > Dungeon Maker can switch off, each on its own, the information hints, the error hints and the gadget name suggestions (all shown by default). In the list of campaign commands the mouse wheel and clicks no longer reach the map or graph behind it, its buttons are centred, and Close is an ordinary button.
- Not tested in game: the Dungeon Maker campaign commands (no campaign here uses them yet), commands through gadgets activated by other gadgets, through variables, quest steps, dialogues, timers and damaged buttons, saving and loading with commands waiting, campaigns that use the mod's variable names themselves, the version recorded in campaign files, the name suggestions in the location editor, the hints shown when pointing at a variable, the Playtest messages, the Campaign commands button, the failure messages, the custom weapon tooltip and damage breakdown with Alt, entries named after their source, the per-screen tool settings, and anything on two computers. The list search and sort, and the dialogue editor's hints, name suggestions and commands list, were tested in single player.
